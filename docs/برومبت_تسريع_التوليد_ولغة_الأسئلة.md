# برومبت: تسريع توليد الأسئلة بالذكاء الاصطناعي + خيار اللغة (عربي/إنجليزي)

الصق هذا لوكيل المنصة (`D:\Shadow\platform`). **مهمتان منفصلتان.**

---

## المهمة 1: خيار لغة الأسئلة المولَّدة (الأهم والأوضح)

**المشكلة:** توليد الأسئلة من سلايدات PDF يطلعها بالإنجليزي دائمًا، بغض النظر عن لغة الأستاذ أو رغبته — حتى لو السلايدات نفسها عربي أو الأستاذ يبي الاختبار عربي.

### التنفيذ
1. أضف بواجهة "توليد بالذكاء الاصطناعي" (`/faculty/exams/new`) **خيار لغة صريح** — قائمة منسدلة أو أزرار راديو: "عربي" / "English"، بجانب حقل "عدد الأسئلة التقريبي" الموجود أصلًا
2. مرّر اختيار اللغة كجزء من الطلب لـ `POST /api/faculty/exams/generate`
3. بملف `src/lib/ai.ts` (أو مكان استدعاء Gemini لتوليد الأسئلة)، **عدّل البرومبت المُرسَل لـ Gemini** ليتضمن توجيهًا صريحًا للغة المطلوبة — مثال:
   ```
   ولّد الأسئلة والخيارات باللغة العربية الفصحى حصرًا، حتى لو كان محتوى السلايدات بالإنجليزية.
   ```
   أو بالإنجليزي حسب اختيار الأستاذ. **لا تعتمد على لغة السلايدات نفسها لتحديد لغة الخرج** — الأستاذ يحدد صراحة.
4. **حالة خاصة يجب تغطيتها:** لو السلايدات بالإنجليزي والأستاذ اختار "عربي"، يفترض Gemini يترجم المفهوم لعربي مو يترجم حرفيًا كلمة بكلمة — تأكد صياغة البرومبت تطلب **"أعد صياغة المفهوم بعربي أكاديمي سليم"** لا **"ترجم النص"**، لتفادي ترجمة آلية ركيكة

### التحقق
ارفع نفس ملف PDF مرتين — مرة باختيار "عربي" ومرة "English" — وأرسل لي الأسئلة الناتجة من الاثنتين للمقارنة، تأكد الفرق حقيقي مو مجرد تسمية الخيار بدون تأثير فعلي بالنتيجة.

## المهمة 2: تسريع توليد الأسئلة

**المشكلة:** توليد الأسئلة (رفع PDF → ضغط "توليد الأسئلة") بطيء محسوس.

### خطوات التشخيص أولًا (لا تخمّن السبب)
1. سجّل توقيت (timestamp) عند:
   - بداية استلام الطلب بـ `/api/faculty/exams/generate`
   - نهاية استخراج/معالجة ملف PDF (لو فيه معالجة قبل إرساله لـ Gemini)
   - بداية استدعاء Gemini API
   - نهاية استلام رد Gemini الكامل
   - نهاية حفظ الأسئلة بقاعدة البيانات
2. أرسل لي الأرقام بالثواني لكل مرحلة — يحدد وين فعليًا الوقت يروح (معالجة الملف؟ Gemini نفسه؟ الحفظ بقاعدة البيانات؟)

### إصلاحات متوقعة حسب نتيجة القياس
- **لو الاختناق باستدعاء Gemini نفسه (الأرجح):** تأكد تستخدم **streaming response** لو الـ SDK يدعمه، وأظهر بالواجهة **مؤشر تقدّم فعلي** (مو دائرة تحميل عامة) — "جاري تحليل السلايدات..." ثم "جاري صياغة الأسئلة..." — يحسّن الإحساس بالسرعة حتى لو الزمن الفعلي ما تغيّر كثير
- **لو الملف كبير ومعالجته قبل الإرسال بطيئة:** راجع هل فيه تحويل غير ضروري للـ PDF (تحويله صور بدل تمريره مباشرة كملف multimodal لـ Gemini، مثلًا) — Gemini يدعم استقبال PDF مباشرة، لا داعي لأي تحويل وسيط لو مو مستخدم فعليًا لغرض واضح
- **لا تقلل عدد الأسئلة المولَّدة كحل للسرعة** — هذا يقايض بالميزة نفسها، الهدف تسريع نفس الكمية، مو تقليلها

### التحقق
قِس نفس المدة (بداية الضغط على "توليد" → ظهور الأسئلة) قبل وبعد التعديل، بنفس ملف PDF بالضبط، وأرسل الرقمين للمقارنة.
